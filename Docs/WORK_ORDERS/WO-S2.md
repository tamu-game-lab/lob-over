# WO-S2 — The simulation in C#: a plain .NET library with parity tests against the JavaScript transcripts

## Goal

`Assets/LOBOver/Sim/` holds a C# port of `Monitor/src/sim/` that Unity compiles through an asmdef with no engine references, and that `dotnet test Sim/LOBOver.Sim.Tests` proves equal to the JavaScript simulation on the goldens and on six recorded transcripts. The headset runs this; the browser runs the JavaScript; both are the same game.

## Read

- `AGENTS.md`, `Docs/ORCHESTRATOR_SHOWCASE.md`
- `Docs/PROTOCOL.md`, `Docs/SCENARIO_SCHEMA.md`, `Docs/WORK_ORDERS/WO-02.md` (the rules; sections 2 and 3) and `WO-05a.md` (the fixes already in the JavaScript)
- Every file in `Monitor/src/sim/` and `Monitor/src/common/rng.js` (the port is line-for-line where possible; same module split, same names)
- `Data/transcripts/*.json` (generated by the orchestrator; the snapshot shape is `sim.view('facilitator')` per day plus every message plus `result`)

## You may change

- `Assets/LOBOver/Sim/**` (source and `LOBOver.Sim.asmdef` with `"noEngineReferences": true`, references `Newtonsoft.Json`), `Sim/**` (`LOBOver.Sim.csproj`, `LOBOver.Sim.Tests/`), `Packages/manifest.json` only to add `"com.unity.nuget.newtonsoft-json": "3.2.1"` if missing, `.gitignore` (`Sim/**/bin/`, `Sim/**/obj/`)

## Build

1. `Sim/LOBOver.Sim.csproj`: `netstandard2.1`, `LangVersion 9`, `Nullable disable`, PackageReference `Newtonsoft.Json 13.0.3`, `<Compile Include="..\Assets\LOBOver\Sim\**\*.cs" LinkBase="Sim" />`, `EnableDefaultCompileItems false`. Unity compiles the same files through the asmdef; nothing in them may reference UnityEngine, System.Text.Json, or C# 10 features.
2. Namespace `LOBOver.Sim`. Public surface: `Scenario.Load(string json, Catalog catalog)`, `Catalog.Load(string json)`, `Sim.Create(Scenario, Catalog, bool pure = false)`, `Tick(double dt)`, `ApplyResult Apply(string seat, JObject cmd)` (commands are the wire JSON, as in the host), `JObject View(string seat)`, `List<JObject> Drain()`, `JObject Serialize()`, `double T`, `string Speed`, `bool Done`, `JObject Result`. Typed read models for Unity on top: `SiteView.From(JObject)` and `PlanView.From(JObject)` with the field names of `views.js`.
3. `Autoplan` (script application, same semantics as `Monitor/src/host/autoplan.js`) and `Pacer` (elapsed-time pacing with fixed 0.01 steps and the catch-up cap, same as `pacing.js`), both engine-free, so WO-S3's director is thin.
4. RNG: the same algorithm and seeding as `rng.js`, bit-exact (test it against 100 values from the JS, recorded in `Sim/LOBOver.Sim.Tests/fixtures/rng_seed_20261020.json`; generate that file with a 5-line Node script and keep it).
5. Numbers: double everywhere, the same operation order as the JavaScript in the crew step, money accrual and conflict check (read the JS literally; do not "simplify" arithmetic).
6. Tests (`xunit`, `net8.0`), run from the repo root:
   - `GoldensTests`: the five cases of `Data/goldens/no_events.json` in pure mode, within the file's tolerances.
   - `ParityTests`, one per transcript in `Data/transcripts/`: replay the script (`Monitor/test/scripts/<name>.json`) through the C# sim with the same dt and command timing as `headless.js`; per day compare the facilitator view's crews (station ±1 ft, status equal, mood equal), trench cells (state equal), boards, truck, money (`spentUsd` ±$100), speed; compare events (ids, `t` ±0.02, card titles), nacks (ids and reasons equal), result (`finishDay` ±0.05, `idleCrewDays` ±0.1, `peakOpenTrenchFt` ±5, `finesUsd`, `deviationsCaught/Missed`, `lost`).
   - `DeterminismTests`: two runs of `slice_play` serialize identically.
   - `ViewFilterTests`: the Plan view has no live positions, the Site view no money, no forbidden words in any message.
7. `Sim/README.md`: 12 lines: build, test, how Unity picks the files up, how to regenerate transcripts after a JS change.

## Acceptance checks

```
dotnet build Sim/LOBOver.Sim.csproj -c Release                       # 0 errors
dotnet test Sim/LOBOver.Sim.Tests -c Release                         # all pass: goldens 5, parity 6 transcripts, determinism, view filters
grep -rn "UnityEngine\|System.Text.Json" Assets/LOBOver/Sim/ ; echo grep-exit=$?   # 1
test -f Assets/LOBOver/Sim/LOBOver.Sim.asmdef && grep -c noEngineReferences Assets/LOBOver/Sim/LOBOver.Sim.asmdef   # 1
git status --short     # only Assets/LOBOver/Sim, Sim/, Packages/manifest.json (+lock), .gitignore
```

## Out of scope

No Unity code, no networking, no scene. If a JavaScript behaviour looks like a bug, port it faithfully and list it in NOTES; the orchestrator decides whether both sides change.
