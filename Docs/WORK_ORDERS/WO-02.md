# WO-02 — Reference simulation (JS), headless runner, golden parity

## Goal

A pure, deterministic simulation module that turns a scenario file into a running job: three crews on a 6,000 ft line, orders that land late, events from the scenario, deviations, permits and hold points, stop-work, conflicts, rain rework, money. A headless runner plays scripted commands against it with no clock pacing and writes a transcript. A golden harness proves the crew model matches the Python oracle in `Data/goldens/no_events.json`. WO-03 wraps this module in a host; nothing in this WO touches networking or pages.

## Build

### 1. Module shape (`src/sim/`)

- `sim.js`: `createSim(scenario, catalog, { pure = false }) → sim` with
  - `sim.tick(dt)` advances `dt` days (use `dt = 0.01`; the host calls it many times per frame)
  - `sim.apply(seat, cmd) → { ok: true, appliedDay } | { ok: false, reason }` for every Plan op (inside a `commit`), Site action and facilitator `ctrl`, exactly as `Docs/PROTOCOL.md` names them
  - `sim.view(seat) → object` the per-seat view of `Docs/PROTOCOL.md` (Plan never sees live positions; Site never sees plan or money; facilitator sees all)
  - `sim.drain() → message[]` host-bound messages produced since the last drain (`event`, `report`, `voice`, `result`, `inspection` replies)
  - `sim.t`, `sim.speed` (`full|slow|paused`), `sim.done`, `sim.result`
  - `sim.serialize()` → JSON of the full state (for transcripts and parity)
- `crews.js` (movement and blocking), `orders.js` (order lifecycle), `events.js` (triggers, effects, options), `deviations.js`, `permits.js` (permits, open-zone limit, hold points), `money.js`, `views.js` (seat filtering), `conflict.js`, `rain.js`. Pure functions on a plain state object; no classes needed; no `Date`, no `Math.random` (use `src/common/rng.js` seeded from `scenario.seed`).
- `headless.js`: CLI, see 4.
- `goldens.js`: CLI, see 5.

### 2. The crew model (must match the oracle exactly in `pure` mode)

- `t` in days, `t = 0` is the morning of Day 1; a crew with `startDay` N starts at `t = N - 1`.
- Each tick, in order `exc`, `pipe`, `back`: if started and not finished, `limit = min(lengthFt, leaderPos)` where exc has no leader, pipe's leader is exc, back's leader is pipe; `newPos = min(pos + rate * mult * dt, limit)`; `work += (newPos - pos) / rate` when it moved; `pos = newPos`; finished when `pos >= lengthFt - 1e-6`.
- `rate` = the crew's current machine's `rateFtPerDay`; `mult` = product of active modifiers (event rate drops as `1 - rateDrop`, rain 0.5, hold/stop/arguing/demobilized/lent-away 0, rework 0 for pipe).
- Peak open trench = max over ticks of `exc.pos - back.pos`.
- Idle days per crew = (finish - start) - work. Crew cost = Σ daily machine cost × days on site × (1 + overheadRate). Days on site end at the crew's own finish, or at demobilization.
- Optional WIP cap (`pure` mode only, for the golden `pull_distance_*` case): exc `limit = min(limit, back.pos + capFt)`.
- `pure` mode disables events, deviations, permits, hold points, orders landing late and conflicts; it exists only to prove the crew model. Everything else uses the full model.

### 3. The full model (rules; every constant comes from the scenario or the catalog, never from code)

- **Speed.** `full` normally; `slow` from the moment an event fires until the next Plan `commit`; `paused` by facilitator `ctrl`. Speed is the host's pacing concern; the sim only exposes it.
- **Orders.** A `commit` turns each op into an `Order {id, op, crew, issuedT, landsT, status}`. `landsT = issuedT` if the Site truck is dismounted within 100 ft of that crew's current position, else the next shift boundary `Math.floor(issuedT) + 1`. Orders apply when they land. `setStart`, `enterPermit`, `enterInspection` and `pay` apply at once (office actions). `radio` re-issues an order with a fresh `landsT` by the same rule. A commit is all-or-none: validate every op first (nack reasons below), then apply.
- **setStart.** `setStart {crew, day}`: nack `"plan locked"` when `plan.locked` or the crew's `locked` is true, nack `"crew already started"` when `t >= crew.startDay - 1`; otherwise the crew's `startDay` becomes `day` (whole days, `>= displayDay`).
- **Hold / resume.** `hold {crew, fromDay?, days?}`: from landing (or from `fromDay` if later) the crew's `mult` is 0 and it bills; with `days` the hold ends by itself after `days`, without it the hold stands until `resume`. `resume` lifts a hold or a stop-work for that crew. Any Plan `commit` after a stop-work lifts the stop-work for the zone's crews unless the commit holds them (design: "stands until Plan commits a plan or resumes").
- **Lend.** `lend {machine, toCrew, days}`: the lender's `mult` is 0 from landing; the machine moves along the haul road and arrives at `toCrew` after `|Δft| / 1500 / 24` days (same day; the city's remobilization delay applies only to `remob` and to hired machines, decision K15). A `lend` of the excavation crew's machine to `pipe` while a P1 is active is the `clear_own` response: the arrival starts the clearing, the lender stays at 0 for the clearing days (`lenderLosesSameDays`), then the machine returns the same way. Otherwise the machine works for `toCrew` for `days` (the receiving crew's rate becomes the lent machine's rate while it has no machine of its own; a crew with its own machine plus a lent one adds the lent rate) and returns.
- **Order a machine.** `order {machine}`: price + `mobilizationUsd` charged at commit; arrives after `leadDays.normal + cities[city].leadDelayDays`; on arrival it replaces the crew's machine (the old one is released at half its price). `pay {item: "hire_excavator", machine}` during an active P1 is the hired-clearing response: same charges and lead time, it clears the collapse in the clearing days for its `sizeClass`, then is released at half price. Rush orders are not exposed (catalog `rushExposedToPlayers: false`).
- **Protect.** `protect {kind, fromFt, toFt}`: price at commit, daily cost while any crew works inside the stretch; `trench_slope` refused in `slopeRefused` cities; `preparationAllowed: false` → nack `"not in the budget"` plus the `prepRefused` voice trigger for `protect` and `order` at any time in that stage (the PM refuses purchases ahead; `pay` for an active or forecast event's options is always allowed).
- **Pay.** `pay {item, machine?}`: `item` must be an `options[].key` of an event that is active, or whose `forecast.inboxDay` has passed (so a pump can be rented when the forecast lands); charges `cost.usd` at once and `cost.perDayUsd` daily to the end of the stage; applies `effect` as this WO describes per event. Unknown or inactive item → nack `"no such response now"`.
- **Demob / remob.** `demob`: billing stops from the next day boundary after landing; `remob`: `demobFeeUsd`, the crew returns after `remobilizationDelayDays`.
- **Permits.** Exc may not pass a zone's end into a zone whose permit is not entered; it idles there (`idleNoPermit`) and bills. `enterPermit` with a code not on the zone's card → nack `"code not on file"`. Entering a permit when open zones (entered and not yet signed) already equal `openZoneLimit` → nack `"city limit: N zones open"`. Stage 1 (`heldBy: "pm"`) starts with all permits entered.
- **Hold points.** Back may not pass a zone's end until `enterInspection` for that zone with the card's number; it idles (`idleHoldPoint`) and bills. The compaction result (`"passed"` in both Texas stages) appears in Plan's inbox when backfill first reaches the zone end. Finishing the job requires zone 4's inspection entered.
- **Stop work.** `stopWork {zone}` (Site dismounted anywhere in that zone): crews in the zone go to `mult 0` after `stopWorkReachHours / 24` days, bill, and their mood rises one level per `moodStepDays` up to 3. Lifted as under Hold / resume.
- **Site actions.** `moveTo {stationFt}`: the truck arrives after `|Δft| / 1500 / 24` days; `mount`/`dismount` only while not moving. `inspect {target}` answers from state at the truck's station (nearest 100 ft stake), with these fixed sources, no invented text: `wall` → the covering `ground.segments[].indicator.wall`, else `ground.defaultIndicator.wall`; `"Wall slumped into the trench."` at a collapse station until cleared; `"Not excavated here yet."` where exc has not passed. `water` → the segment's `indicator.water`, else the default; `"Standing water in the trench bottom."` at a collapse station, and at every open station during rain and rework. `machine` → the nearest crew within 100 ft: `"<crew name>: <catalog label>, plate <sizeClass>"`, else `"No machine within sight."`. `protection` → `"<catalog label> in place, <from> to <to>"` or `"No protection here."`. `board` → `"Zone N board: permit <number>"` / `"Zone N board: no permit posted"` plus `"inspection <number>"` when signed. `sky` → `"Clear."` / `"Towers building to the south."` / `"Rain."`. `ticket` → an order in transit: `"Delivery ticket: <label>, due Day N"`, else `"No truck at the gate."`. `crew` → nearest crew: `"Working."` / `"Idle, waiting on <leader>."` / `"Held by the office since Day N."` / `"Stopped: stop-work."` / `"Arguing with <crew>."` / `"Demobilized."` followed by the mood word `calm | grumbling | angry | furious` for levels 0–3. `pipe` → `"No pipe here yet."` / `"Pipe laid, open trench."` / `"Backfilled."`. Per-station trench state for the Site view: `undug` until exc passes the stake, `open` until pipe passes, `piped` until back passes, then `backfilled`; `water` is `seep` at open stations inside a seepage segment, `standing` at the collapse station and at open stations during rain and rework, else `none`; `wall` is `slumped` at the collapse station until cleared. `flag {stationFt, note}` adds `{stationFt, day, note}` to Plan's `flags[]`. `listen` at arguing crews returns the two `conflict` lines; at a held crew its `heldDayN` line for its mood; else `"Nothing to hear."`. `confirm {orderId, outcome}` needs the order landed at a crew within 100 ft.
- **Events.** Check triggers each tick (`crewReaches` fires when the crew's pos first reaches `ft`; `day` fires at `t = day - 1`). On firing: speed `slow`; emit `event` to `visibleTo` seats (card = `card`, or `cardWhenProtected` when protection covers `stationFt`); apply `rateDrop` to `hits` for `durationDays`. P1: pipe stays at `mult 0` until a response resolves it: `clear_own` (a `lend` of exc's machine to pipe, see Lend) → clearing days by that excavator's `sizeClass` (× `severityByProtection[kind]` if protection covers the station, rounded to 0.5), pipe resumes after; `pay emergency_shoring` → resumes after `resumeAfterDays`; `pay hire_excavator {machine}` → resumes after lead days + clearing days by the hired size; no response → stays stopped (the slow clock is the pressure). A2: all crews × 0.5 for 2 days; at the rain's start record `openFt = exc.pos - back.pos`; at the rain's end `reworkDays = ceil(openFt / 500) × daysPer500Ft × (a pump paid for before the rain ends ? 0.5 : 1)`; pipe `mult 0` for `reworkDays` after the rain ends. The pump's `rainRateRestore` sets the listed crews' rain multiplier back to 1 for the rest of the rain. Forecast: the inbox item on `forecast.inboxDay` is generated from `forecast.text` (not listed in `inbox[]`), Site `sky` becomes `towersSouth` from `skyFromDay`, `rain` during.
- **Deviations.** F1 `firstRadioOrder`: the first order (in commit order, first matching op in the first commit that has one) with `op` in `ops` whose `landsT > issuedT` lands but is not applied; it applies when Plan `radio`s it (new landing by the normal rule). Caught if Site `confirm notDone` on it before the next day boundary. F2 `firstUnpermittedBoundary`: the first time exc reaches an unpermitted boundary it continues `overshootFt` into the zone, then idles; `permitFineUsd` is charged; not if Site is dismounted within 100 ft of the boundary or exc is held. F3 `protectStretchMisses`: nothing to simulate; the result card counts it caught if Site `inspect protection` happened at the protected stretch before the event fired and the stretch did not cover `stationFt`. F5 is not authored in these stages; implement the hook, no behaviour.
- **Conflicts.** Each tick for each (trailing, leader) pair where the trailing crew is working (`mult > 0`, not already blocked by the leader): if `trailing.pos + trailing.rate × trailing.mult × 1 > leader.pos + leader.rate × leader.mult × 1` (would cross within the next day), fire a conflict **once per pair per stage** (decision K7): both crews `arguing` (`mult 0`, billing), speed `slow`, `voice` with the two foremen's `conflict` lines to Site, a facts-only `event` card to Site. Resolved by the next Plan commit that `hold`s or `demob`s the trailing crew (any other commit → nack `"conflict: hold or demobilize the trailing crew"`); the leader resumes at once, the trailing crew per the order. After that first argument, a trailing crew that catches its leader again simply idles against it (`min(pos, leaderPos)`), bills, and its mood rises; it counts in `idleCrewDays`.
- **Money.** `spentUsd` accrues per tick: Σ billing crews' daily × dt × (1 + overheadRate) + protection daily fees × dt × (1 + overheadRate); purchases, mobilization, `demobFeeUsd`, fines and option costs at face value when charged. Lose when `spentUsd > budgetUsd` or `t > deadlineDay - 1`; the result then carries `lost: "budget" | "deadline"`.
- **Daily report.** At each integer `t`: `report {day, feetByCrew (floor), spendUsd, notes}` and Plan's `reportedLines` advance. Plan's "today" estimate = reported + rate × elapsed with band ± `uncertaintyBandFt`.
- **Result.** When back finishes (zone 4 signed) or on a loss: `finishDay` (t), `promisedDay`, `budgetUsd`, `spentUsd`, `idleCrewDays` (sum of per-crew idle), `peakOpenTrenchFt`, `finesUsd`, `deviationsCaught/Missed`, `events[]` (id, day, option chosen, days lost, protection present), `changeLog[]` (every commit with day and ops), `lines {planned, actual}` as polylines per crew. Facts only; no adjectives, no grades.
- **Voice triggers.** Emit `voice {lineIds, seats}` for `stageStart` (plan + site), `prepRefused` (plan), `holdCommitted` / `demobCommitted` (plan), `orderLanded` (plan), `orderNotDone` (plan), `conflict` (site), `heldDay1..3` (site, when a held crew's mood reaches 1..3), `stageEnd` (plan + site). Look lines up by `trigger` in `scenario.lines`; no line → no message.

### 4. Headless runner (`src/sim/headless.js`)

`node Monitor/src/sim/headless.js <scenario.json> [--script <script.json>] [--out <transcript.json>] [--pure]`

- A script is `[{ "t": 5.1, "seat": "plan", "cmd": {...} }, ...]`, applied when the sim reaches `t` (before the tick).
- Runs with `dt 0.01`, no pacing, until `sim.done` or `t > deadlineDay + 5` (safety stop, reported in the transcript).
- Transcript: `{ scenario, seed, snapshots: [sim.view('facilitator') at every integer t], messages: [every drained message with its t], result }`. Numbers rounded to 3 decimals so two runs compare byte-for-byte.
- Ship three scripts in `test/scripts/`:
  - `stage1_noaction.json`: empty; must end with `lost: "deadline"` (pipe never cleared), finish absent.
  - `stage1_pm_play.json`: Site rides to 7+20 before Day 6; at the collapse Site stops work on zone 1, Plan commits `lend` (exc's machine → pipe) + `hold back 2 days`; Site rides to the excavator, finds the lend not carried out (F1), confirms `notDone`, Plan `radio`s it, Site confirms `done`; Site rides to the backfill crew and confirms the hold; at the argument Plan holds back until pipe is 2 days ahead; when the Day 17 forecast lands Plan does not rent the pump (push stage); Plan enters inspection numbers as zones close; nobody buys anything else. Expect: the collapse `event` message at `t = 5.0 ± 0.02`; `finishDay` greater than `promisedDay` (35) and less than `deadlineDay - 1`; no `lost`. Report the actual finish, idle days and spend in NOTES: the design doc's "36 to 38" predates the order-lag and rework rules and will be corrected from your numbers.
  - `stage2_pull_play.json`: huddle: `setStart back 12`, `protect trench_box 600 900`; Rules holds permits: Plan enters zone 1 and 2 codes at start, 3 and 4 as zones sign; Site stands at the excavator when the zone 2 and 3 boundaries are reached (so F2 cannot fire there); same collapse handling (the box halves the clearing); Plan `pay`s the pump when the Day 17 forecast lands. Expect: `finishDay` less than `deadlineDay - 1`, no `lost`, `idleCrewDays` lower than the Stage 1 script's, `peakOpenTrenchFt` ≤ 3000 (two zones), the collapse card `cardWhenProtected`, `finesUsd` 0. Report the numbers in NOTES.

### 5. Golden harness (`src/sim/goldens.js`)

`node Monitor/src/sim/goldens.js Data/goldens/no_events.json` runs every case in `pure` mode (build a minimal scenario from the case's `startDay` and `machines`, 6,000 ft, `capFt` as the WIP cap), compares `finishDay`, `idleDays` per crew, `crewCostUsd`, `peakOpenTrenchFt` with the tolerances in the file's `_doc`, prints one line per case with PASS/FAIL and the deltas, exits 0 only if all pass.

### 6. Tests (`test/sim*.test.js`)

Unit tests for: order landing (Site present vs absent), `setStart` nacks, `hold` with and without `days`, F1 behaviour and catch, permit gating and the open-zone limit nack, hold point gating, stop-work reach and mood steps, P1 durations by size and under a box (2 → 1 day for Standard), rain rework arithmetic (1,300 ft open → 3 days; with pump → 1.5) and `rainRateRestore`, conflict detection, resolution and the once-per-pair rule, `inspect` answers at a seepage station and at the collapse station, budget/deadline loss, determinism (two headless runs of `stage1_pm_play` produce identical transcripts), view filtering (Plan view has no live positions; Site view has no budget; the words `correct|wrong|score|well done|should have` appear in no Plan or Site view and no host-bound message; the facilitator view and internal ids are exempt).
