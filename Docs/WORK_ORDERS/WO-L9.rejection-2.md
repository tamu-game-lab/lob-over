## Failed

1. **The seats' `host left` close arrives late for a seat that joined after the hibernation idle.** `cd Relay && npm.cmd test` fails at `relay.test.js:53` (`assert.deepEqual(await seat.closed(), { code: 1000, reason: 'host left' })`, the 5-second poll) with `Timed out waiting for test condition`, in both rounds. The orchestrator's trace of the same sequence (a probe copy of the test with the sockets' states printed every 500 ms after `host.socket.close()`): the `site` seat, joined before the 12-second idle, reaches `readyState` 3 within 60 ms and `/rooms` is `[]` at once; the `rules` seat, joined after the idle, sits at `readyState` 2 (CLOSING: it has the Worker's close frame and waits for the connection to end) for 6 to 11 seconds and then closes; with the wait extended the whole test passes ("Forwarding both ways, broadcast, joins/leaves, hibernation, CORS, 409 and host-left passed"). Isolated probes without the test's sequence (clean close, abrupt close, close after a 13-second idle, each with traffic before the close) close the seat in 30 to 70 ms. So the Worker does its part (`Room.hostLeft` sends the close; `/rooms` empties immediately) and local workerd finishes the handshake of a recently accepted hibernatable socket late. Required: the test waits up to 15 seconds for each seat's close after the host leaves (a longer poll there only), and `Room.webSocketClose` does not call `socket.close()` a second time on a socket the room already closed in `hostLeft` (mark the attachment `closing: true` when the room closes a seat and skip the second close), so the handshake has nothing left to wait on; the round-1 closed-attachment change in `Directory` stays.

2. **The e2e's static server writes headers twice.** `node --test Monitor/e2e/relay.e2e.js` fails with `Error [ERR_HTTP_HEADERS_SENT]: Cannot write headers after they are sent to the client at ServerResponse.writeHead (relay.e2e.js:22)`: `staticServer` calls `response.writeHead(200, ...)` before `await readFile(path)`, and when the file is missing (a request the page makes for a file the showcase build does not ship) the catch block calls `writeHead(404)` on a response that already has headers, which crashes the test process. Required: read the file first, then write the headers and the body; a missing file answers 404 once; the page's requests for missing files are listed in the test's diagnostic so a real gap shows.
