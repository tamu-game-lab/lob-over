# WO-04 — Printed kit generator: field manual, permit and inspection cards, zone ledger, tokens, job sign (PDF)

## Goal

`python Paper/make_kit.py Data/Scenarios/stage1_texas.json` writes `Paper/out/stage1_texas/` with: `manual.pdf` (letter, stapled, about 12 pages), `cards.pdf` (permit cards and inspection cards, 4 per page, cut lines), `ledger.pdf` (the zone ledger strip, landscape), `tokens.pdf` (open-trench tokens, one per 500 ft), `jobsign.pdf` (one card), and `kit_index.txt` listing every code that was printed. Everything printed comes from the scenario file and `Paper/manual_v0.md`, so the paper always matches the build. The same command works for `stage2_texas.json`.

## Read

- `AGENTS.md`
- `Paper/manual_v0.md` (the manual's text and structure; you typeset it, you do not rewrite it)
- `Docs/DESIGN_v0.md`: "The field manual", "Paper kit"
- `Data/Scenarios/*.json` (`permits`, `inspections`, `job.sign`, `kit`, `events[].options[].check`, `ground`), `Data/catalog.json` (`workbookDurations`, `machines`, `cities`)

## You may change

- `Paper/**` except `Paper/manual_v0.md`

## Build

1. `Paper/make_kit.py` (Python 3.11, `reportlab`, already installed by the orchestrator; standard library otherwise). Arguments: scenario path, optional `--out`.
2. **Manual**: typeset `Paper/manual_v0.md` section by section; `kit.manualPages` in the scenario selects and orders the sections (`front_rule`, `city_<city>`, `indicators`, situation codes, `permits_holdpoints`, `lookup`, `procedures`). Fill the placeholders the markdown marks as `{{...}}`. Dotted names are JSON paths into the scenario (`job.sign.cityCode`, `permits.openZoneLimit`, `rules.demobFeeUsd`, `rules.permitFineUsd`) or the catalog (`city.*` = `cities[scenario.city]`, `protection.*`). Derived placeholders, defined here: `job.zoneCount` = number of zones; `job.zoneLengthFt` = the first zone's length; `city.openTrenchLimitZones` from the catalog city; `permits.heldByText` = "all issued and posted by the PM before Day 1" when `heldBy` is `pm`, else "held by Rules; the city allows N zone(s) open at a time" with N = `permits.openZoneLimit`; `permits.cardsTable` = a table Zone | Permit number | Code from `permits.cards`; `inspections.cardsTable` = Zone | Inspection card number from `inspections.cards`; `inspections.checklistBullets` = `inspections.checklist` as a bulleted list with checkboxes. Also emit `manual.txt` (the same text, plain) beside the PDF for the word test. Keep the Keep Talking look: one situation per page, numbered procedures with the seat in the margin, tables with ruled lines, no colour needed. Page footer: stage id and page number. Cover: title from the scenario, the three seats, "Rules seat only".
3. **Cards**: permit cards show the zone, the permit number, and the code `dddd-c` in large type with the text "Read the code to Plan. Return this card when the zone is backfilled and signed." Inspection cards show the zone, the checklist (three boxes) and the number. Mark Stage 1 permit cards "ISSUED BY PM" across the top when `permits.heldBy == "pm"`.
4. **Ledger strip**: stations across (every 500 ft labelled, zone boundaries heavy), three crew rows plus four boxes per zone (permit day, pipe complete day, inspection day, backfill day), landscape letter, two copies.
5. **Tokens**: `lengthFt / openTrenchTokenFt` tokens (12 for 6,000 ft), 2 in circles, "500 ft open" each, cut lines.
6. **Job sign card**: city code, pipe, contract days, the stage title; matches the sign the VR scene will show.
7. `kit_index.txt`: every code and number printed, one per line, in the form `permit zone 1 TX-0141 4821-5`, so the orchestrator can diff it against the scenario.
8. Never print anything from `events[].options[].effect`, `deviations[]`, `events[].trigger`, `cardWhenProtected`, or a `_validate` note. The manual tells Rules how to diagnose and what the checks are, never which option is "right", and it does not reveal when or where events will fire.
9. Tests: `Paper/test_make_kit.py` (a plain script that exits non-zero on failure) checks the index matches the scenario's cards, the PDFs exist and have page counts within a stated range (`pypdf`, installed by the orchestrator), and that `manual.txt` and `kit_index.txt` contain none of `when right|when wrong|right choice|well done|correct answer|score` and none of the scenario's `deviations[].id` or `when.kind` strings, event ids, or trigger stations (`7+20`). The word "wrong" alone is allowed (the manual names "wrong delivery" and "wrong station" as field facts).

## Acceptance checks

```
python Paper/make_kit.py Data/Scenarios/stage1_texas.json && python Paper/make_kit.py Data/Scenarios/stage2_texas.json
ls Paper/out/stage1_texas/ Paper/out/stage2_texas/                               # manual.pdf cards.pdf ledger.pdf tokens.pdf jobsign.pdf kit_index.txt in each
python Paper/test_make_kit.py ; echo exit=$?                                      # exit=0
grep -c "^permit zone" Paper/out/stage1_texas/kit_index.txt                       # 4
grep -E "7\+20|ev_p1|firstRadioOrder|cardWhenProtected|f1_first_radio_order|f2_push_ahead|f3_box_misplaced" -r Paper/out/*/kit_index.txt Paper/out/*/manual.txt ; echo grep-exit=$?   # grep-exit=1 (never printed)
git status --short                                                                # only Paper/ (Paper/out is gitignored)
```

The orchestrator opens `manual.pdf` page 1, a situation page and a city page as images and checks them against `Paper/manual_v0.md`.

## Out of scope

Do not edit the manual text. If a `{{placeholder}}` has no source in the scenario or catalog, print `[to validate]` in its place and list it in NOTES.
